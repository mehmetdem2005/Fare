# S9.0–S9.1: verifiable Android build identity + bounded chunk CPU trace

User's second Android JSON (2026-11-22): fps_estimated=7.9, frame_mean_ms=126.01, frame_p95_ms=142.89, frame_p99_ms=148.95, max_chunk_load_ms=1078.87, max_cache_save_ms=329.8, active_chunks=25. The report contained NONE of S8-D's compulsory `quality_level`, `render_scale_3d` or `chunk_stage_peak_ms` keys, nor S8-C's `longest_frame_ms`; therefore it is from a pre-S8-D metrics binary or an earlier clipboard/JSON. It CANNOT validate S8-D/E graphics/cache effects.

S8 Android export used package name `org.farevadisi.riverdiagnostics`, version 8 and a NEW temporary debug keystore on every GitHub CI run. Attempting to install a differently signed APK over the same package fails; a device may continue launching the old package. This change creates a unique package name `org.farevadisi.s9b<8-digit-commit>` for each GitHub build, with an unmistakable Android app label and an on-screen HUD + JSON build SHA. S8 remains side-by-side; do not uninstall it to run S9. CI stamps GITHUB_SHA after checkout and before Godot import; the source checkout's fallback identity is labeled local/unstamped. A single APK cannot claim a SHA from a separate CI run.

The S9.1 low-frequency trace captures each chunk's coords, cache source, queue wait, CPU stage max/p50/p95/p99 (cache_read, terrain_mesh, collider, vegetation, river_fx, publish), 5 worst cases and a 256-job ring. **This does not measure GPU upload timing.** The existing S8 metric keys are retained but the format marker is now `fare-s9-device-metrics-v1`, so old/new reports cannot be confused.

For a baseline-only A/B test, the FPS panel exposes a fixed-scene toggle when the full 25 chunks have loaded and the queue is empty. It stops new queue/retire work only while the player remains in the original center chunk, and automatically resumes if the center chunk changes; ordinary physics and water continue. It is diagnostic, not a shipping gameplay mode.
