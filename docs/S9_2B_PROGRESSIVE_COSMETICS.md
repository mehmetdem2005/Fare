# S9.2b — Streaming without single-frame cosmetic bursts

Real Android S9-d74eb1f1 reported warm river chunk max ~193.6ms, with ~59ms for mist (invisible in Fast), ~76ms stones, ~33ms tree/grass. Cold chunks sometimes exceeded 1s: already addressed for z=-3..12 in S9.2a read-only baked corridor.

This patch preserves original synchronous API (default _add_chunk for all bake/test tools) and introduces an Android-only incremental cosmetics pipeline after **terrain + collision + river water + major boulder collision** have been prepared. RandomNumberGenerator is preserved across batches; same ordered candidate loops generate identical deterministic transforms. Trees: 6 candidates per micro-step, grass: 15, stones: 14, mist: 1; scheduler executes at most ~3ms target time per engine _process after those steps. A single slow API call may exceed this target and is measured, not hidden. Ready chunks retain full 25-window collision before cosmetic staging. Distant decorations may pop when completed; no invisible collider, and unload discards stale jobs. Fixed-scene A/B toggle refuses until all cosmetic work complete.

Fast quality does not create invisible 60ms mist. Balanced/Full can later regenerate identical mist geometry in separate incremental candidates, preserving river visuals and material. GDScript CPU work remains on main thread (safe), no GPU upload on worker, no flow/river/soil/rig changes.

Godot CI compares deterministic MultiMesh transforms against original synchronous creation for Pines/Grass/FinePebbles/Cobbles/Mist, asserts collision/water presence before cosmetics, checks stale job discard and 49-bone rig. Note: baseline p95 frame in fixed scene was ~50ms already on device; this patch alone cannot fix all render and thermal stutter, nor the infinite-world uncached CPU path beyond baked corridor. Test same route with S9.2b real Android APK, especially 0..200m river and first cold chunk outside coverage. Evaluate new cosmetic_phase_peak_ms, wall_gap_max_ms and p95/p99, not merely FPS.
